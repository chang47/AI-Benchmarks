# Task 22 "Broken Tabletop" — independent panel review (glm, round 1)

## Part A — My own spec plan

### A.1 Approach in one paragraph
Build **one reference app** sized and shaped for a single real evening session, correct by construction, proven by a **hidden suite written blind from the docs** (task-21-style three-way reconciliation: spec vs. tests vs. implementation, disagreements resolved by the SRD/spec, never by "what the code does"). Then plant **11 bugs as stored patches** — each validated solo, en masse, and against 2–3 alternative correct fixes — and ship the bugged repo as 22a and the clean repo as 22b. Grading is a frozen points checklist over **documented surfaces only** (wire protocol, documented test-mode hooks, rendered UI); the only subjectivity is 3-vote yes/no judges on `FINDINGS.md`. Everything (F2P/sentinel/P2P lists, points, bands, judge questions, fixture, pristine scaffold hash) is frozen in `FREEZE_MANIFEST.json` before any run, with a controls matrix reproduced before freeze.

### A.2 Key decisions
- **D1 Scope.** Core = the one-evening-session slice: join-by-link identity, one-port authoritative server, scenes/grid/pan-zoom, tokens with drag/nudge/hidden, manual cell fog, ruler, server-side dice + chat/whispers/roll cards, single-class sheets with derived stats, damage/heal/death pipeline, conditions, combat tracker, vendored SRD subset, autosave + export, test mode. Everything else is backlog (AoE templates, dynamic lighting, macros, multiclass, drawing, …) and is Variant B's raw material. The line is hard: the build agent may not add backlog items.
- **D2 Architecture.** npm-workspaces monorepo: `shared` (rules, dice, protocol types), `server` (Node + TS + ws), `client` (Vite + React + TS). DOM/SVG rendering with stable attributes — deterministic, dependency-light, probeable without pixels.
- **D3 Identity & auth.** Invite link → display name → personal rejoin link; per-window identity in the **URL fragment** (two windows in one browser, refresh-stable). **WebSocket auth via first message, never a query string** — Tailscale Funnel strips query params on WS upgrade (tailscale/tailscale#18651). Auto-reconnect + full resync is mandatory, not a nicety (serve-mode sockets drop every 10–40 s, tailscale#18827).
- **D4 Determinism.** All dice server-side, seeded PRNG per game; test mode (env flag, off by default, loopback-only) exposes reset / load-fixture / set-seed / forced-faces and **changes no game rule** — enforced by a parity regression group (see C5).
- **D5 Grading surfaces.** Security/visibility bugs and any behavior fully observable in wire messages → **protocol tests** (server must enforce). Only genuinely client-rendered symptoms → browser tests. Target: **≤ 2 browser-graded bugs** (B04 zoom-drop, B08 ghost tokens); grade B07 and B11 at the protocol level (C3).
- **D6 Bug catalog.** 5 reported + 6 unreported across: info leak (server projection ×2), permission, tracker lifecycle, client store lifecycle, domain rules ×2, parser, coordinate transform, boundary contract — plus a **persistence** reserve promoted to primary if anything fails validation (C11). Each bug: F2P + local sentinels + alt-fix validation + ≤60 s two-window repro.
- **D7 Scoring.** Reported: all-or-nothing per bug (its F2P **and** sentinels). Unreported: F2P + sentinels + 3-vote FINDINGS confirmation, tier-weighted. Penalty −4 per failing subsystem regression group (13 groups; visible suite diagnostic-only), floor 0. Controls: clean=full, untouched=0, each single fix=exactly its points, client-only security fix=0, delete-the-feature=0−penalty, findings-without-fixes=0.
- **D8 Packaging.** Buggy repo generated **once** on the build machine and frozen as an artifact (never re-patched at package time — CRLF lesson from task 18); fresh single-commit git, neutral author; node_modules **copied** from the frozen lockfile (offline, unshared); grader rebuilds from a pristine scaffold, copying **source directories** only.
- **D9 Offline browser.** Decide at G1: either vendor a runner + pinned Chromium (same playwright pin as task 18) into the workspace so the visible e2e and the grader both work offline, or drop visible e2e to unit + protocol smoke. Don't leave it implicit.
- **D10 Anti-cheat.** Hidden tests never in the container; agent test edits ignored; no web tools during runs; test-mode parity sentinels; varied hidden inputs (never the complaint examples); FINDINGS judged on the timeout snapshot with a repro requirement per entry.
- **D11 Name.** Not "Lantern" — it collides with the existing open-source VTT "Lantern Tabletop" (C1). Pick and collision-check at G1.
- **D12 Calibration.** Before freeze, run a reference agent (or hand-apply) the 5 reported fixes under the real 120-min sandbox budget. If it doesn't fit comfortably, thin the app or surface the bugs — never assume.

### A.3 My bug-catalog delta vs. the draft
Keep B02, B03, B04, B05, B06, B08, B09, B10 essentially as drafted. Change: **B01** complaint reworded to cover fog explicitly, both F2P tests stay gating (C4); **B07** story rewritten (validate-the-cast-store-the-original + `>` comparator in a tie-break chain) and re-graded to protocol (C3/C8); **B11** re-graded to protocol so the client "+1" hack stops earning points (C3). Add: **persistence reserve R6** (autosave drops fog or the round; restart-the-server-on-camera repro) (C11). Tiers and the 5/6 reported/unreported split stay as the draft has them.

### A.4 Top risks, ranked
1. **Agent time budget** — 5 reported + 6 unreported fixes in ~16k navigable lines in 120 min is tight; D12 calibration is the only real control.
2. **Browser grader flakiness on Windows** — minimized by D5 (protocol-grade everything you can).
3. **Harness dependencies** — text-based 3-vote judges (29/69 points), workspace-prepare with copied node_modules, artifact exclusions. Build judges first; without them 22a is unscorable.
4. **Tailscale realities** — WS query-param stripping and periodic 1001 drops; design auth and reconnect for them, and test Funnel with a real phone at G2.
5. **Validation matrix machine time** — ~40–60 full grades ≈ 7–10 h serial; budget it explicitly.
6. **Test-mode reward hacking** — fixture/seed special-casing; parity group + varied inputs.
7. **Scope/line creep** — pre-declared demotions (scene preview, embedded-image export, duplicate scene, cantrip scaling); measure with the frozen counter at G1.
8. **SRD 5.2.1 exactness** — creatures were renamed (Goblin → Goblin Warrior, now Fey); verify names and the four [verify] rules against the PDF before tests are written.
9. **Windows packaging** — CRLF (freeze artifacts, don't re-patch), MAX_PATH with deep node_modules, EPERM-on-rename retries for autosave.
10. **Public-repo leak** — catalog is public by choice; deny web tools during runs and sequence publication if possible.

## Part B — Adversarial critique of Draft v0

### B.0 What the draft gets right (keep, don't churn)
Blind hidden-test authoring with reconciliation (TST-02) is the single best integrity feature. The per-viewer projection spine, stored patches with solo/en-masse/alt-fix validation, the controls table, the fresh single-commit repo, sentinel-gated all-or-nothing scoring, complaints that read like real players, and §4 ("the design deliberately creates bug sites") are all right. DOM/SVG over canvas is the correct call for deterministic grading. The self-flagged weak spots are honest and mostly correct.

### B.1 Blockers (must fix before freeze)

**C1. The app name collides with an existing VTT.** "Lantern Tabletop" is a live, open-source, web-based VTT (lanterntt.com; github.com/owl-factory/lantern — TypeScript/React, explicitly "an alternative to Roll20"). A public benchmark repo and videos that name a competitor's product in the same category is an optics/search/legal mess. OQ-1 should be pre-answered "anything but Lantern," with a fresh collision check across VTT and RPG-tool namespaces at G1.

**C2. WebSocket auth and reconnect are designed against an idealized Tailscale.** Two current upstream issues: tailscale/tailscale#18651 — Funnel/serve **strips query parameters from WebSocket upgrade requests**; tailscale#18827 — serve-mode WebSockets **drop every 10–40 s with close 1001**. Consequences: (a) the obvious implementation (`wss://host/ws?key=…`) breaks on exactly the deployment Josh chose — the spec must mandate first-frame (or subprotocol) auth and forbid query-string credentials; (b) reconnect + full resync (APP-04) is load-bearing, not a nicety, and the B06 history-replay path will fire constantly in real sessions — good for realism, but G2 must actually test Funnel with a phone, and the perf budget should include a reconnect burst. The draft assumes "WebSockets just work through Serve/Funnel" (weak spot f) — they work, with caveats that change the auth design.

**C3. B07 and B11 should be protocol-graded; the browser-graded set shrinks to B04 + B08.**
- **B11:** the fog cell set is fully observable in the player's fog snapshot/update messages, so the off-by-one is deterministically testable at the protocol level. As drafted (browser-graded "so a fix on either side counts"), a client-side hack (send `end+1`) earns 3 points while leaving the server violating PROTOCOL.md's documented inclusive-rectangle contract — and it would still pass the fog P2P groups, because bigger rects reveal the whole map fine. That's paying points for a spec-violating "fix." Protocol-grade it; a client-only fix scores 0, consistent with the documented contract.
- **B07:** APP-91 already pins server-side numeric ordering ("all three shall order numerically"), and the tracker order is broadcast. A protocol test (GM types "7"/"12"/"30" → assert snapshot order) catches every legitimate fix site: client parse (sends numbers → sorts right), server coercion, server comparator. Only a display-only client sort "fix" fails — and that isn't a fix, since both windows render the server's order. Bonus: B07 leaves the flaky browser set, attacking the draft's own weak spot (c) and shaving browser time.

**C4. B01's F2P-2 prices a reasonable fix at 0/10 — the likeliest unfair moment in the task.** The complaint ("I could see the goblins before our GM revealed them… they just kind of showed up for a bit") reads as fog *or* hidden; the on-camera repro demos only the hidden-flag case. An agent who fixes exactly the hidden-token leak — matching the complaint as worded — fails F2P-2 and gets 0 of the largest reported bug. Resolve, don't hedge: state the invariant once in APP-32/APP-12 ("a drag-stream message may only reach viewers who can currently see that token"), reword the complaint around "before the GM revealed them" (fog semantics), keep both tests gating. If Josh prefers the narrower complaint, demote F2P-2 to a non-gating diagnostic — but pick one; the draft's current state is the worst of both.

**C5. Test mode is an open reward-hacking surface.** Hidden tests always run in test mode, and TESTING.md documents the hooks. An agent can special-case the fixture or seed ("if testMode, clamp healing", "if fixture X, inclusive fog loop") and pass F2P tests without fixing anything. CAT-07 (varied inputs) helps but isn't sufficient. Add a **parity regression group**: boot the server *without* the test flag, load state via the documented import API, and assert the same fog/dice/tracker/HP behaviors; any test-mode branch that alters game rules fails it. Also have the README state that test mode changes no rule and that the hooks are public API (breaking them is a regression, not a refactor).

**C6. Packaging holes that will bite on Windows.** (a) Apply patches **once** on the build machine and freeze the buggy repo as an artifact — never re-apply at package time (task 18's CRLF lesson: anchors must survive line-ending variation; not re-patching makes it moot). (b) Make it a CAT constraint that every bug patch — and every legitimate fix — lives entirely inside the allow-listed source directories, and make the allow-list **directory-based** so agent-added files survive the copy. (c) Decide where the visible e2e's browser binaries come from offline (D9): shipping a runner + pinned Chromium is a real disk/memory cost; not shipping it means the visible suite can't include browser smoke. (d) MAX_PATH: pre-copied node_modules under a deep `tasks/22a/...` path will blow 260 characters on Windows — prepare the workspace at a short root. (e) APP-110 "atomic writes": rename-over-existing on Windows can transiently EPERM under antivirus/indexer contention — require temp-file + rename + bounded retry, and say so.

**C7. The judge dependency is on the critical path and treated as a footnote.** 29 of 69 points require text-based 3-vote majority judging, which the harness doesn't have yet (§12 admits it). If it slips, 22a is unscorable. Build it first. Also specify: judges see the FINDINGS.md **snapshot taken at timeout** (not a post-hoc edit); the judge model configuration is frozen in the manifest; vote failures retry with a defined quorum rule.

### B.2 Major flaws

**C8. B07's story is contrived (the draft knows it) — rewrite rather than ship.** The "loosened for a short-lived notes field" justification invokes a second fictional feature whose corpse is itself suspicious. Realistic replacement with zero fictional machinery: the client sends the raw text-field value (no `type=number`); the server validator checks `Number.isFinite(Number(v))` but **stores the original** (validate-the-cast, store-the-original — a genuine classic); the comparator chain (initiative → modifier → name) uses `>`, so mixed values compare lexically. Note the reference must *not* use `b - a` — numeric coercion would mask the bug — and the tie-break chain is precisely what makes a `>` comparator plausible. Verify the "before" order: string-descending "9" > "21" > "14" gives 9, 21, 14 ✓.

**C9. The 14th regression group double-counts.** The pristine visible suite overlaps the 13 subsystem groups, so one bad tokens refactor costs −8. Make the visible-suite run diagnostic-only (report, no points) and keep 13 penalty groups. Cleaner for the video too.

**C10. FINDINGS.md needs a required entry format, or honest agents lose bonus points to judge false-negatives.** An agent that writes a competent fix summary ("routed quick-edit through the shared heal rule") without describing the faulty *behavior* risks a no-vote under GRD-01. Ship a 2-line template in the prompt: **what was wrong (what a player would see) + how you reproduced it**. The repro line doubles as the shotgun-FINDINGS defense: amend GRD-01 so entries with no observed repro are judged no. Keep GRD-02 (no penalty for wrong entries) exactly as is.

**C11. No persistence bug despite persistence being core and a regression group.** The catalog's seven subsystems skip APP-110/111 entirely. Add reserve **R6** and promote it if any primary fails validation: autosave persists sheets but drops fog (or the tracker round); repro = restart the server on camera → the cellar is lit again / round counter reset. ~20 s, non-coder-legible, fills the one empty class, and exercises a lifecycle story distinct from B03/B08.

**C12. The validation matrix's machine cost is unstated.** TST-06 implies clean ×3, each bug solo (11), all-bugs (1), 2–3 alternative fixes × 11, plus the §7.4 controls — roughly 40–60 full grades ≈ 7–10 h serial at ~10 min each. Budget it in the build plan or it will be quietly skipped. Also add judge validation to TST-06: run the 6 FINDINGS questions against three synthetic FINDINGS styles (terse diff-log, prose, shotgun-with-repros) and record the votes before freezing the questions.

**C13. Copying the data dir into the grader's build invites rule-editing "fixes".** An agent can make an HP or fog test pass by editing vendored data/rules tables. Exclude runtime and vendored data from the agent-copied set (the reset hook reloads fixtures anyway) — or, if data must be copied, pin it with multi-value P2P assertions. Prefer excluding.

**C14. Agents must be told the protocol is a contract.** A well-meaning cleanup renaming message types zeroes every protocol test (−4 × many groups, no bug points) with no warning. One sentence in README/PROTOCOL.md: the wire protocol and the test-mode hooks are a stable public surface for external tools; renaming them is a breaking change. Cheap fairness, no leak.

**C15. Browser locators: roles/labels primary, test ids minimal and pinned.** A5 lists test ids as a grading surface, but an innocent refactor that drops a `data-testid` would fail browser F2P unfairly. Make roles/labels the primary locators, keep the documented test-id set as small as possible, and pin its existence with a P2P assertion so removing ids is a *visible* regression, not a silent unfair fail.

**C16. SRD 5.2.1 naming is partially resolvable now — do it.** The 2024/5.2 renames hit the fixture directly: **Goblin → Goblin Warrior** (Goblin Minion and Goblin Boss also exist), and goblins are now typed **Fey**; Bandit / Bandit Captain and Wolf exist under those names. The fixture, hidden tests, and complaint text must use exact 5.2.1 names, and the Fey typing matters if anything keys on creature type. The remaining OQ-6 items (diagonal cost, resistance/vulnerability order, short-rest minimum-1, temp HP on long rest) still need a PDF pass — assign one owner, ~1 h, **before** hidden tests are written, not during reconciliation.

**C17. The client line budget is optimistic and the 500-line citation is unowned.** 8k client lines for sheets + compendium + tracker + fog + chat + viewport + polish is tight, and CSS counts toward the total. Pre-declare demotions (scene preview, export-with-embedded-images → JSON-only, duplicate scene, cantrip scaling) rather than raising the 25k ceiling, and measure with the frozen counter at G1. Separately: "no source file over 500 lines, per Josh's global rule" appears nowhere in the problem statement — verify the rule exists or delete the sentence; a spec shouldn't carry unowned constraints.

**C18. The 120-minute budget is asserted, never calibrated.** Before freeze, have a reference agent apply the 5 reported fixes inside the actual sandbox under the real clock. If a strong model needs >90 min, the app is too big or the bugs too buried — thin §2 or surface the bugs; don't discover this in the first scored run. This is the cheapest insurance the plan can buy.

### B.3 Minor
- **C19.** The GM key rides in the URL fragment and will be screen-shared on camera. Demo launcher prints a masked link; the demo banner hides the key.
- **C20.** B02's "after" should be pinned to "Aldric does not move in either window"; the client's display of the rejection stays unspecified (TST-03 already allows any).
- **C21.** Fog perf: a 60×60 scene is up to 3.6k elements; render fog as row-merged rects, and keep timing budgets generous per TST-03.
- **C22.** Grader hygiene on Windows: kill the full process tree (server + Chrome) between phases; one Chrome at a time, serial (task 18 memory lesson).
- **C23.** Define `d%` explicitly as 1–100, and make B10's F2P pin totals with forced faces, not just die counts.
- **C24.** TST-09's arithmetic sits at the edge (~45 s build + ~1 min protocol + ~4 min browser + 18 judge votes + startup ≈ 8–10 min). Decide now whether judges run inside the grade or asynchronously patch results afterward; freeze the grader timeout accordingly.
- **C25.** 22b's "scripted replay of each FEATURES.md how-to" isn't implementable generically. For round 1, say an operator or LLM-driven browser performs each how-to while the sniffer records player sockets, and keep the whole item diagnostic — the draft already keeps it unscored, so say the honest version.
- **C26.** Complaint attribution is fine (two reporters), but note Jo is offline in the demo fixture — the B02 complaint is about a past session, which the current wording already implies; keep it that way.

### B.4 Positions on the draft's open questions
- **OQ-1 (name):** rename — not "Lantern" (C1). Shortlist 3–5 candidates, collision-check VTT/RPG-tool namespaces at G1.
- **OQ-2 (RULES.md):** ship it as written. Domain bugs should be findable by doc-vs-code audit; the remaining difficulty is locating the code path that skips the rule, which the doc doesn't reveal. Trimming it mostly punishes models without deep 5E knowledge — a knowledge test, not a debugging test.
- **OQ-3 (rebuttal line):** include it as a clause inside the one extra line ("If you believe a complaint isn't a bug, say so in FINDINGS.md instead of fixing it"). Clarification 5 already grants the affordance (0 points, no penalty); prior art says stating it cuts gaming, and a clause keeps the "one line" framing intact.
- **OQ-4 (web tools):** deny WebSearch/WebFetch for both variants' runs. The spec and patches are public by decision; without denial the catalog is a search away. If the harness can't deny, sequence the catalog's publication until after round-1 videos.
- **OQ-5 (client-only fixes):** keep 0. The "looks fixed but a modified client could still do it" beat is core video material, and the README documents the authoritative-server model, so the requirement is discoverable and fair. Partial credit would muddy the security story.
- **OQ-6 ([verify] items):** creature names resolved by C16 (Goblin Warrior / Bandit / Wolf; goblins are Fey). The remaining four rules: one named owner checks the PDF before hidden-test authoring begins.
- **OQ-7 (Chrome):** vendor Chromium pinned to the same Playwright version task 18's holdout uses (1.63). System Chrome auto-updates and will drift between freeze and the video series; a frozen manifest deserves a frozen browser.
- **OQ-8 (penalty):** keep −4, over **13** groups, with the visible suite diagnostic-only (C9). "Fixed all five, broke two subsystems → 32" is a sensible on-camera story.

### B.5 Verdict
The draft's spine is right and should not be churned: authoritative server + per-viewer projection, blind test authoring, stored patches with alt-fix validation, controls, and complaint realism are all strong, and its self-criticism is accurate. Before freeze it needs, in order: the name fixed (C1); WS auth/reconnect designed for real Tailscale behavior (C2); B07/B11 re-graded to protocol and B07's story rewritten (C3/C8); B01's complaint/invariant resolved (C4); a test-mode parity group (C5); the packaging list closed out (C6); text judges built first (C7); and a 120-minute calibration run (C18). With those landed, I would freeze this spec.
